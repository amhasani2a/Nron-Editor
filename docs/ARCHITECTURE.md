# معماری Nron Editor

## نمای کلی

Nron از الگوی **هسته‌ی بومی + رابط وب** (native-core + webview) پیروی می‌کند که توسط **Tauri v2** فراهم می‌شود. این همان معماری‌ای است که اجازه می‌دهد از یک کدبیس، هم دسکتاپ (ویندوز) و هم موبایل (اندروید) بسازیم.

```
┌──────────────────────────────────┐
│            Webview (UI)              │  HTML + CSS + Vanilla JS
│  index.html / css / js modules      │  → responsive, RTL, offline
└─────────────┬────────────────┘
               │  window.__TAURI__.core.invoke(...)
               ▼
┌──────────────────────────────────┐
│           Rust core (Tauri)          │  src-tauri/src
│  count_stats · find_matches          │  → fast, native
│  markdown_to_html · html_to_markdown │
│  build_epub · core_info              │
└──────────────────────────────────┘
```

## چرا این معماری؟

- **سرعت**: محاسبات سنگین (شمارش، جستجو، ساخت EPUB) در Rust انجام می‌شود.
- **سبکی**: برعکس Electron، Tauri از WebView سیستم استفاده می‌کند → حجم بسیار کمتر.
- **کراس‌پلتفرم**: یک هسته، چند هدف (ویندوز/اندروید/...).
- **تداوم کار**: رابط کاربری وب مستقل از هسته توسعه داده می‌شود.

## الگوی Progressive Enhancement

فایل `js/core-bridge.js` وجود `window.__TAURI__` را تشخیص می‌دهد:
- **داخل Tauri**: عملیات سنگین به هسته‌ی Rust سپرده می‌شود.
- **داخل مرورگر (پیش‌نمایش)**: پیاده‌سازی جایگزین JS اجرا می‌شود.

این یعنی رابط کاربری را می‌توان حتی بدون کامپایل Rust در مرورگر باز کرد و تست کرد.

## ذخیره‌سازی

تمام داده‌ها (اسناد، مقالات، تنظیمات، تاریخچه) در **IndexedDB** مرورگر ذخیره می‌شوند → کاملاً آفلاین.

## فرمان‌های هسته (Rust commands)

| فرمان | کاربرد |
|-------|--------|
| `count_stats(text)` | شمارش کلمات/نویسه/جمله/پاراگراف + زمان مطالعه |
| `find_matches(text, query)` | یافتن همه‌ی تطابق‌ها |
| `markdown_to_html(md)` | تبدیل مارک‌داون به HTML |
| `html_to_markdown(html)` | تبدیل HTML به مارک‌داون |
| `build_epub(title, author, body)` | ساخت EPUB 3 استاندارد |
| `core_info()` | وضعیت هسته |

## تست
